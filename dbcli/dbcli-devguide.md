# dbcli 模块说明

> 适用版本：0.2.2。本文说明 dbcli 的组成、运行方式与使用约定；完整命令手册见
> `dbcli/README.adoc`（英文）与 `dbcli/README-CN.adoc`（中文）。

## 1. 这个模块能做什么

`dbcli` 是 SlackerDB 的命令行客户端，提供四种用法：

- **交互式控制台**：在终端里逐条输入 SQL 与命令；
- **批处理**：`--execute <脚本>` 或从标准输入读脚本，跑完返回退出码；
- **结果比对**：把本次运行的数据输出与参考文件比较，作为回归门禁（`--reference`）；
- **并发与远程**：作业（`_JOB`，线程或独立进程）、同步屏障、SSH/SFTP（`_SSH`）。

依赖方向固定为 `dbcli → plsql → common`，并使用项目自带的 JDBC 驱动。`dbcli` 不被其它模块依赖，
因此可以把内部实现保持为包私有。

## 2. 目录与包

| 包                     | 内容                                   |
|-----------------------|--------------------------------------|
| `org.slackerdb.dbcli` | 进程入口、命令行参数、运行形态、收尾（退出码与比对）           |
| `engine`              | 脚本引擎：逐行累积 → 分析 → 分派 → 输出             |
| `engine.command`      | 一条命令一个类（`_SET`/`_ASSERT`/`_SPOOL`/…） |
| `script`              | 本模块使用的 SQL/命令语法与 IR                  |
| `sql`                 | 数据库执行层与结果渲染                          |
| `assertion`           | `_ASSERT` 的求值与结果模型                   |
| `job`                 | 作业的定义、启动、等待、停止与超时                    |
| `rendezvous`          | 作业之间的同步点（同进程 / 跨进程）                  |
| `compare`             | `_COMPARE` 的文件比对与报告                  |
| `report`              | `--reference` 的收尾比对                  |
| `ssh`                 | SSH 远端命令与 SFTP                       |
| `repl`                | 交互式控制台的取行与循环                         |
| `daemon`              | 后台运行（`--daemon`）与 pid 文件             |
| `help`                | `_HELP` 文案（与 README 同源）              |
| `common`              | 多个包共用的小类型（路径/数值解析、命令结果项）             |

每个包都有 `package-info.java`，说明该包的职责、阅读顺序与关键约定，建议从那里开始读。

## 3. 一次运行的过程

1. **参数**：`Main` 构造命令树，`Cli` 解析参数并决定运行形态（控制台 / 脚本 / 标准输入 / 后台）。
2. **基准目录**：脚本里的相对路径以**脚本所在目录**为基准；命令行选项按**进程当前目录**解析。
3. **执行**：脚本按行进入引擎；引擎把"能收尾的一段"交给分析器：
   - 还没写完 → 继续读下一行（控制台给出续行提示）；
   - 是 SQL → 交给执行层；
   - 是命令 → 交给对应的命令实现或命令分派器。
4. **输出**：数据、状态、诊断都走标准输出；被执行语句的原文与控制台转录只写日志。
5. **收尾**：写出日志/比对产物，计算退出码。

## 4. 使用约定

### 输出

- 标准输出是**可逐字节比对**的产物：行尾固定为 `\n`，不随平台变化。
- 错误也写在标准输出上（dbcli 不使用标准错误），每条错误同时计数。
- `_SET FEEDBACK OFF` 关掉状态行与错误消息；`--silent` 关掉终端上的全部输出，但文件产物照常写。

### 退出码

| 结果                                   | 退出码                   |
|--------------------------------------|-----------------------|
| 正常结束                                 | `0`                   |
| `_EXIT n` / `_WHENEVER ERROR EXIT n` | `n`                   |
| 脚本内部错误（SQL 错、断言失败、比对不一致、作业失败）        | 仍是 `0`（只打印并计数）        |
| `--reference` 不一致或参考文件不存在            | `1`（脚本自己给了非 0 时以脚本为准） |
| 用法错误                                 | `2`                   |
| 工具自身崩溃                               | `70` / `255`          |

> 要让"脚本里出现过错误"变成失败，请在脚本里写 `_WHENEVER ERROR EXIT 1` 或结尾 `_EXIT 1`。

### 会话与连接

- `_SET` 的选项（含 `AUTOCOMMIT`、`TIMEOUT`）在**重连后继续生效**。

### 作业

- 作业默认在线程里运行；`mode=process` 时在独立进程里运行，可硬超时并结束整棵进程树。
- `_JOB WAIT` 不写 `timeout=` 会一直等；等待超时只是"这次没等到"，作业仍在运行。
- `_JOB ABORT` / `_JOB SHUTDOWN` 是**请求**停止。作业正常响应时立即进入 `ABORTED` / `SHUTDOWN`；
  若作业暂时没有响应，状态保持 `RUNNING`，并在它真正结束后落到对应终态。

### SSH

- `_SSH execute` **默认不限**远端命令的运行时长；用 `_SSH SET TIMEOUT = <秒>` 设置上限
  （`0` 恢复不限，设置对当前连接立即生效并被后续连接继承）。
- 设置上限后超时会中断远端命令，已产生的输出照常显示，并给出一条错误提示。

### 守护运行

- `--daemon true` 把脚本交给后台副本，父进程打印副本的 pid 后立即返回；`--pidfile` 可选。
- 报告 pid 之前父进程会先清理上一次留下的 pid 文件；pid 文件以整体替换的方式写入，
  因此不会读到写了一半的内容。

## 5. 扩展指引

- **新增一条 `_` 命令**：语法（`src/main/antlr4/.../BaseParser.g4`）→ IR（`script/SqlIrVisitor`）→
  实现（`engine/command` 下一个类）→ 登记（`engine.command/CommandCatalog`）→ 文案
  （`help/HelpCatalog` 与 README）→ 测试。
- **新增一个 `_SET` 选项**：在 `engine/SetOption` 中声明（默认值、类型、校验、落地点都在那里）。
- **新增结果输出形式**：从 `sql/ResultRenderers` 进入，保持"单元格文本先归一、再排版"的层次。

## 6. 构建与测试

```bash
mvn -o -B -pl dbcli -am test                 # 单元测试（含依赖模块）
mvn -o -B -pl dbcli -am -DskipTests package  # 生成可执行 jar 与源码包
```

测试不依赖外部数据库或 SSH 主机：数据库相关用项目自带的 SQLite 驱动，SSH/SFTP 用假实现，
需要真实环境的用例默认跳过。
